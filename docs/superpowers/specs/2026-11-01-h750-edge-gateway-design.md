# 工业边缘网关 V2.0：北极星 H750 移植设计

日期：2026-11-01。状态：用户已批准并执行；实际验收边界见 docs/verification.md。

## 目标与已有条件

- 将 https://github.com/zgd-dev/-V2.0 的网关应用移植到用户已连接的正点原子北极星 STM32H750 开发板。
- 用户确认屏幕为正点原子 4.3 英寸 RGB 触摸屏，800×480；通过 DAP 下载；目前没有外接 Wi-Fi、传感器或其他模块。
- 以已编译、烧录成功的本机北极星 H750 官方例程及板卡资料作为硬件基线，保留原项目的 FreeRTOS、LVGL、Modbus RTU、MQTT、日志、离线缓存、重连、看门狗和息屏功能。
- 建立独立、可复现构建的移植项目，在用户 Edge 已登录的 GitHub 账号下创建新仓库并上传；提供中文说明、接线表、采购清单和实际验证记录。

## 已选路线与替代方案

用户已选择 A。

- A：保留 ESP8266 AT 固件 Wi-Fi 和 RS485/Modbus，替换底层板级驱动并适配大屏。复用板载存储和 RS485，改动集中、利于与上游对照学习。
- B：改用板载 LAN8720 以太网。可省 Wi-Fi 模块，但需要集成网络协议栈；ETH_MDIO 与 USART2_TX 共用 PA2，还必须调整 RS485 接口。本次不实现。

## 硬件与存储分工

以本机 `STM32H750_CORE V1.2.pdf`、`CNF750_H750 V1.4.pdf`、硬件参考手册及已成功运行的官方例程相互核对。底板实际版本若与资料存在差异，以通信和器件 ID 实测为准。

| 功能 | 资源与约束 |
| --- | --- |
| 主控 | STM32H750XBHx，Keil 工程使用已验证可用的 ARM Compiler 5.06 update 6 |
| 代码 | 片内 128KB Flash 保存启动与必要初始化，板载 8MB QSPI W25Q64 映射到 0x90000000 保存其余代码/常量 |
| RGB 屏 | 使用北极星 LCD/LTDC BSP，横屏 800×480、RGB565，帧缓冲放板载 SDRAM |
| 触摸 | 复用北极星触摸 BSP，自动识别支持的屏幕与控制器，向 LVGL 提供真实触摸坐标 |
| 数据存储 | 使用独立 SPI2 W25Q256（32MB），PF10 片选、PB13/PB14/PB15 总线；绝不把 QSPI 代码 Flash 用作运行数据存储 |
| 日志与缓存 | 原逻辑保留各 4MB；建议迁至数据 Flash 最后 8MB：日志 [0x01800000,0x01C00000)，缓存 [0x01C00000,0x02000000)。必须验证四字节地址访问，禁止地址回卷与整片擦除；数据 Flash 前 24MB 保留给原厂资源/字库 |
| RS485 | 板载 SP3485，USART2 PA2/PA3、9600 8N1；通过 PCF8574 P6 切换收发方向，不沿用 F411 的 PB0 方向脚 |
| RS485 跳线 | 按底板 P9 将 USART2_TX 接收发器 DI、USART2_RX 接 RO；接线文档附正确方向，禁止仅凭网络名称猜 TX/RX |
| Wi-Fi | 预留 USART3 PB10/PB11；选 ESP8266 AT 固件模块，通过 P10/ATK MODULE 或独立串口线接入。USART1 保留调试输出 |
| 调试与下载 | 使用现有 DAP/SWD，保留已验证的片内与 `ATK-DNH750_QSPI_W25Q64JV.FLM` 两种下载算法 |

建议地址为本次移植的实现选择，不代表已在硬件完成存储验证。若检测到数据 Flash 型号/容量不符，记录明确错误并停止擦写，不退回代码 Flash。

## 软件结构与适配

最终项目目录采用英文路径，原仓库保持可回溯；新 GitHub 仓库仅提交所需源码、许可证、Keil 工程、构建脚本及文档，排除编译缓存和个人配置。

- H750 平台层：使用官方 H7 HAL、启动文件、时钟、QSPI 启动、SDRAM、MPU/cache、RGB 屏、触摸、SPI 与 PCF8574 的板级实现，保留第三方原有署名和许可证。
- 业务层：保留原应用的功能和数据流；把 UART、GPIO、SPI、时间基准等硬件依赖收敛到 H750 适配接口。
- FreeRTOS：使用与 Cortex-M7 匹配的端口，统一 SysTick/HAL 时间基准，核对中断优先级和任务栈；看门狗以关键任务活动状态为依据，避免只要喂狗任务仍运行就掩盖业务卡死。
- LVGL：沿用上游版本与中文字体，重新适配 800×480 布局、刷屏和触摸；主界面、日志页、联网/采集状态、运行时间和息屏唤醒可操作。
- 屏幕与缓存：明确 SDRAM 帧缓冲的 MPU/cache 策略；初版以一致性和可靠显示优先，不在缺少证据时声称完成 DMA2D 性能优化。
- UART：初版优先中断接收与有界环形缓冲，避免直接套用 F4 UART 寄存器名和未经处理的 H7 DMA/cache 逻辑。
- Flash：四字节寻址、分区边界、扇区擦除、日志循环和缓存掉电恢复需要验证；离线数据仅在约定的发送成功条件满足后标记已发，不能把本机发送成功描述成云端持久化确认。
- Modbus：保留两类设备和可配置地址/寄存器/倍率/字节顺序；上游默认温湿度从站 1、03H、起始 0x0001，光照从站 2、03H、起始 0x0002。采购时不要求不同厂家的寄存器布局天然相同。
- 配置：Wi-Fi SSID/密码、云端 UID、主题放在不入库的本地配置文件；仓库提供无凭据的示例配置。不得原样发布上游硬编码的 Wi-Fi 密码与云端密钥，也不复制到新的提交历史中。

## 当前硬件下的运行行为

- 无 ESP8266、无传感器也能进入主界面、操作触摸和日志页，显示“未配置/未连接/离线”等真实状态。
- 不生成看似真实的传感器数值，不向上游作者的云账号发送数据；演示数据如另行提供，必须明确标为演示且与真实采集分开。
- 缺失的外设不会造成无限等待、持续重启或界面冻结；通信失败有超时、退避和可见日志。
- 默认不启用有线以太网，防止 PA2 与 RS485 冲突。

## 验收与证据边界

当前必须完成：

1. 从新项目目录通过脚本或 Keil 重新构建，生成可烧录 AXF/HEX，记录编译器、支持包版本与编译结果。
2. 用 DAP 烧录并通过校验，确认程序启动；记录下载日志。
3. 验证 800×480 RGB 显示、触摸、主界面/日志切换、运行时间推进和唤醒；通过串口、调试状态和用户实物反馈交叉核实，不能只以烧录成功推断屏幕正常。
4. 读取板载数据 Flash ID、验证分区内专用测试扇区的擦写/读回及边界；不得做整片擦除，首次初始化只影响新分配的日志/缓存分区。
5. 验证无模块时任务仍运行、网络和采集显示缺失状态，关键任务健康状态可观察。
6. 为可在主机执行的协议/分区逻辑增加必要的边界验证；避免只检查宏值或复制实现的形式化测试。

因硬件缺失而明确延期、不得声称已完成：真实 RS485 传感器数值/故障恢复、ESP8266 上网、用户 MQTT 云端上报、实际断网/重连后的端到端补传。相应代码和配置仍在本次移植范围内，提供后续验收步骤。

## 采购清单交付要求

区分“已板载，无需购买”“运行原项目链路必需”“按所选器件条件购买”“可选调试附件”。至少包含：

- ESP8266 UART/AT 模块及适配连接方式，3.3V 逻辑、稳定供电、2.4GHz Wi-Fi；是否需要转接板由所选模块封装决定。
- 支持 Modbus RTU 的 RS485 温湿度传感器和光照传感器各 1，提供采购规格、可配置从站地址、供电要求和寄存器适配说明。
- 与所选传感器电压匹配的直流电源、RS485 A/B 双绞线、必要的公共参考地及接线端子/跳线帽/杜邦线。
- 终端电阻按总线两端已有电阻核算；板上已有 120Ω，不能盲目重复并联。
- 调试用 USB-RS485 作为可选项；开发板、4.3 寸屏、DAP、额外 SPI Flash、外置 RS485 收发器不列为必购。
- 电源电压以最终传感器规格为准，传感器的 12V/24V 电源不得直接接入 MCU 的 3.3V/5V 引脚。
